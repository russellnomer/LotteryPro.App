Replit’s direction is mostly sound, but I’d tighten a few parts before you hand it back.

The biggest correction is in task #9: `@capacitor/browser` does **not** open native Safari; on iOS it uses `SFSafariViewController`, which is an in-app system browser. If you truly want the device’s default browser, Capacitor’s newer `@capacitor/inappbrowser` docs show `openInExternalBrowser(...)` for that. ([Capacitor][1])

Also, the App Store compliance reasoning should be framed more carefully. Apple requires in-app purchase for digital goods and subscriptions sold inside apps in general, but Apple updated its App Review Guidelines in May 2025 for the U.S. storefront around buttons, external links, and calls to action. That means “hide all Stripe/PayPal on iOS” is a conservative approach, not a universal truth in every storefront/use case. ([Apple Developer][2])

One more nuance: Apple’s “reader app” external-link entitlement is narrow. It applies to apps whose primary function is books, audio, music, video, newspapers, or magazines, and those apps cannot also offer in-app purchases on iOS while using that entitlement. LotteryPro probably should not assume it qualifies for that path. ([Apple Developer][3])

For task #8, the Capacitor setup itself is correct in principle. Capacitor’s config file sets `appId`, `appName`, and `webDir`, and `webDir` is what `npx cap sync` uses when copying the built web assets into the native project. Keeping `webDir: 'dist'` is appropriate for a standard Vite build if your build already outputs to `dist/`. ([Capacitor][4])

I would send Replit this revised guidance:

### What to keep

* Install `@capacitor/core`, `@capacitor/cli`, and `@capacitor/ios`.
* Add `capacitor.config.ts` with:

  * `appName: 'LotteryPro'`
  * `appId: 'com.lotterypro.app'`
  * `webDir: 'dist'`
* Do **not** run `npx cap add ios` in Linux.
* Verify `npm run build` outputs to `dist/`. ([Capacitor][4])

### What to change in task #9

* Use a small platform helper based on `Capacitor.getPlatform()`.
* On iOS, gate the existing web checkout UI behind a platform check.
* Show an IAP placeholder only if you are preparing for real Apple IAP implementation.
* For external links:

  * use `@capacitor/inappbrowser` with `openInExternalBrowser(...)` if the requirement is “open in Safari / default browser”
  * do **not** use `@capacitor/browser` for that requirement, because it stays in-app on iOS. ([Capacitor][5])

### What I would rewrite in their spec

Replace this:

> “use Capacitor's Browser.open() plugin so they launch in native Safari on iOS”

with this:

> “use Capacitor’s `@capacitor/inappbrowser` plugin and `openInExternalBrowser()` on iOS when the requirement is to open the device’s default browser; fall back to `window.open(..., '_blank')` on web.” ([Capacitor][5])

### Best-practice caveat for monetization

I would also tell them:

> “Implement iOS payment gating conservatively for App Store review, but do not hardcode the assumption that all external payment links are always forbidden on every iOS storefront. Keep the payment presentation behind a platform/compliance abstraction so rules can vary by storefront and future Apple policy changes.” ([Apple Developer][6])
